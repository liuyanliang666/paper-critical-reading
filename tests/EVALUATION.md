# Validation record

Validated on 2026-09-05 with Python 3.12, PyMuPDF 1.28.2, and MCP Python SDK 1.29.1.

## Automated checks

`python -m unittest discover -v`: 18 tests passed with the MCP extra installed.
`node --check paper_reader/web/reader.js`: passed.

The PDF fixture is generated by `make_pdf` in `test_reader.py`. It is deliberately synthetic: it contains two columns, repeated sentences, a wrapped sentence, a hyphenated word, and a second page referring to a missing table. Rotation and cropping variants are generated separately. Citation rectangles are checked against independently extracted PDF search rectangles. A rendered page was also inspected to confirm that selecting the repeated sentence in the right column highlights that occurrence.

The MCP test starts a real stdio server, discovers its tools, imports the PDF, searches and reads it, creates/reloads a citation, opens the reader URL over HTTP, retrieves a page image, and checks that fabricated quotations fail. Publisher-page resolution and URL caching are tested with controlled download responses; those are not live publisher tests.

## Skill forward test

An independent agent used the Chinese skill and CLI, without an expected answer, for two consecutive questions about the same fixture.

| Question | Observed behavior |
|---|---|
| What inputs does the method need at test time, and does this material establish success in new environments? | Answered in Chinese with verified original-text links; distinguished the input statement from missing success-rate evidence; inspected both pages and identified the absent table. |
| What behavior does the navigation policy claim? | Gave a focused follow-up with the exact original statement, reused the saved paper, and qualified the unsupported claim. The line-end hyphenated word produced a citation with two line boxes. |

All four citation URLs from these answers returned HTTP 200 when the reader was running with the same cache and port. Both skill files also passed the skill frontmatter validator.

## Not verified here

- A live arXiv import could not run because this execution environment could not resolve the arXiv host. The resolver must also be checked on an ordinary network with accessible real papers, including complex layouts and publisher pages.
- Codex and Claude Desktop GUI interaction and browser click/zoom behavior were not exercised here. Configuration generation, MCP protocol behavior, JavaScript syntax, HTTP assets, and underlying PDF geometry were checked separately.
- The tested client integration is a local reader opened through a normal link. Native sidebar embedding is not implemented.
